# 동아리 게시물 순서 저장 — 백엔드 연동 필요

현재 저장소에는 순서 저장 API 명세나 백엔드 구현이 없습니다.
프런트엔드의 순서 편집 UI는 아래 **제안 규격**으로 연결되어 있으며,
실제 서버 지원은 확인되지 않았습니다. 서버에서 이 규격을 구현하거나,
확정된 규격에 맞춰 `updateClubPostOrder`를 변경해야 저장이 동작합니다.
실패한 요청은 편집 화면에 오류를 표시하며 저장된 것으로 처리하지 않습니다.

## 저장 요청

`PATCH /api/clubs/{clubId}/posts/order`

인증: `Authorization: Bearer <accessToken>`

```json
{ "postIds": [31, 12, 45] }
```

해당 동아리 전체 게시물 ID를 원하는 표시 순서대로 전송합니다.
성공 응답: `200 { "success": true, "data": null }` 또는 `204`.

서버는 요청자가 해당 동아리의 현재 PRESIDENT인지 검사해야 합니다.
다른 동아리 ID, 중복 ID, 누락된 ID를 거부하고 전체 순서를 트랜잭션으로 저장합니다.
편집 중 게시물 추가·삭제로 전체 ID 집합이 달라졌다면 409로 거부합니다.
권한 없음은 403, 인증 실패는 401로 응답합니다.

## 목록 조회

기존 `GET /api/clubs/{clubId}/posts?page=0&size=4`가 모든 사용자에게
저장된 순서로 **정렬한 다음 페이지를 나눠** 반환해야 합니다.
새 게시물은 맨 앞에 추가하고 삭제 시 나머지 상대 순서를 유지합니다.
정렬 미지정 동아리는 기존 기본 순서를 유지합니다.

프런트엔드는 편집 시 모든 페이지를 읽습니다. 저장 성공 후 해당 동아리의
목록 캐시를 무효화하고 첫 페이지로 이동합니다. 취소는 서버 요청 없이 변경을 폐기합니다.
